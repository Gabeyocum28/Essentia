# VM Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the API and a self-sufficient worker (embed on demand, crawl when idle) on the Oracle VM behind the VM's existing Caddy, at `https://essentia.gabeyocum.com`, with the iOS app pointed at it and nothing running on the Mac.

**Architecture:** One Docker image (the existing `deploy/Dockerfile`) runs two services in a compose stack at `~/stacks/essentia` on the VM: `essentia-api` (uvicorn) and `essentia-worker` (`python -m music_recommendations.worker`). Both join the VM's external `web` network, where the shared Caddy stack (`~/stacks/caddy`) already terminates TLS for other sites; one site block routes `/api/*` to the API. The worker is `scripts/embed_worker.py` moved into the package plus a crawl step that walks Deezer charts and the jazz artist graph whenever the queue is empty, and a first-boot seed of the 30 fixture tracks. The Atlas URI lives only in `~/stacks/essentia/.env` on the VM.

**Tech Stack:** Docker Compose v5, Caddy 2 (already running), uvicorn, pymongo, the Deezer public API.

**Spec:** `docs/superpowers/specs/2026-09-11-oracle-atlas-migration-design.md`, section 6 (and §8 for error handling).

## Global Constraints

- Follow the VM's existing conventions exactly: stacks live under `/home/ubuntu/stacks/<name>`, containers join the external Docker network `web`, nothing but Caddy binds host ports, Caddy config is `/home/ubuntu/stacks/caddy/Caddyfile` (reload with `docker compose -f /home/ubuntu/stacks/caddy/docker-compose.yml exec caddy caddy reload --config /etc/caddy/Caddyfile`). Do not modify the `polyrhythmd`, `blog`, or `caddy` stacks except to append the Essentia site block to the Caddyfile (back it up first, as `Caddyfile.bak.<epoch>` like the existing backups).
- Secrets: `MONGODB_URI` is never written to git, never printed, never pasted into chat. `deploy/.env.example` holds placeholders; the real `.env` is created on the VM by the user.
- Public URLs: API at `https://essentia.gabeyocum.com/api/...` (Caddy strips `/api`); `PUBLIC_BASE_URL=https://essentia.gabeyocum.com/api` so preview URLs handed to clients resolve.
- Container budgets on the 2-core, 12 GB VM shared with two other stacks: api `mem_limit: 4g, cpus: 1.5`, worker `mem_limit: 3g, cpus: 1.0`. One uvicorn worker process (its endpoints are sync and run on a threadpool; a second process would double the in-RAM corpus matrix and TensorFlow).
- Worker env: `CORPUS_CAP` (default 100000), `CRAWL_INTERVAL_S` (default 60), `MONGODB_URI`, `MONGODB_DB`.
- Branch `vm-deploy` off `main`. Run `python3 -m pytest -q` before every commit.
- Do not touch `web/` (sub-project 4).

Add these functions before `_tick`:

```python
def _enqueue_new(tracks: list[dict]) -> int:
    """Store metadata and queue every track we have not analyzed; count queued."""
    queued = 0
    for track in tracks:
        if store.get_features(track["track_id"]) is not None:
            continue
        store.put_track_meta(track)
        if store.enqueue_embed(track["track_id"]):
            queued += 1
    return queued


def seed_fixture_if_empty() -> int:
    """First boot: queue the 30 fixture tracks so the app has something to rank."""
    if store.corpus_size() > 0 or store.queued_count() > 0:
        return 0
    tracks = json.loads(FIXTURE.read_text())["tracks"]
    n = _enqueue_new(tracks)
    print(f"[worker] empty corpus: queued {n} fixture tracks", flush=True)
    return n


def crawl_step() -> int:
    """One bounded slice of crawling: a genre chart or one jazz root's neighbours.

    Alternates so breadth (charts across genres) and depth (the jazz artist
    graph the app is about) both keep growing. The cursor lives in Atlas so a
    restart continues where it left off.
    """
    if store.corpus_size() >= CORPUS_CAP or store.queued_count() >= MAX_QUEUED:
        return 0
    state = store.get_state("crawl") or {"step": 0}
    step = int(state.get("step", 0))
    genres = list(crawl.GENRES)
    if step % 2 == 0:
        genre = genres[(step // 2) % len(genres)]
        tracks = crawl.from_charts([genre], per_genre=100)
        source = f"chart {crawl.GENRES[genre]}"
    else:
        root = crawl.ROOTS[(step // 2) % len(crawl.ROOTS)]
        tracks = crawl.snowball([root], hops=1, per_artist=20)
        source = f"snowball {root}"
    n = _enqueue_new(tracks)
    store.put_state("crawl", {"step": step + 1})
    print(f"[worker] crawl {source}: {len(tracks)} candidates, {n} queued", flush=True)
    return n
```
