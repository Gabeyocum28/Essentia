# Corpus Deduplication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop the corpus from accumulating re-releases of the same recording, never show a duplicate in results, and retire the duplicates already stored.

**Measured 2026-09-13 (20,068 analyzed):** 7.0% exact title+artist duplicates, 12.9% after stripping remaster/live/feat suffixes, 8.8% of rows have a near-identical embedding (cosine > 0.995), and 320 of 323 sampled near-identical pairs were the same recording under another Deezer id; the rest were genuine covers.

**Architecture:** A pure `dedupe_key(title, artist)` normalizer lives in `server/dedupe.py`. Every stored track carries `dedupe_key` (indexed). The crawler skips candidates whose key exists (in the store or earlier in the same batch). Tracks retired by the backfill carry `duplicate_of: <primary id>` and are excluded from `corpus_ids`, `base_matrix`, `tracks_since` and `get_many_features`-driven paths, so every endpoint stops seeing them without further changes. As a second net, `/recommend` and `/viz/map` collapse result candidates that share the seed's or an earlier result's key, or whose embedding is within 0.995 cosine of an earlier result. A script marks existing duplicates (dry-run by default).

**Tech Stack:** Python, pymongo/mongomock, numpy.

## Global Constraints

- Contract unchanged: `Track` objects keep exactly the contract fields; `dedupe_key`/`duplicate_of` never appear in responses.
- Covers survive: the key includes the normalized artist; embedding-based collapsing only applies within a result list, never to the stored corpus.
- Backfill keeps the earliest `analyzed_at` per key as the primary. `--apply` required to write; the default prints what it would do.
- Tests: `python3 -m pytest -q` green before each commit. Branch `dedupe` off `main`.

## Facts

- `store.put_track(track, features)` and `put_track_meta(track)` upsert `_meta(track)` = title/artist/album/artwork_url; `base_matrix()` and `corpus_ids()` filter on `analyzed_at` `$exists`; `tracks_since` on `analyzed_at $gte`; `get_many_features(ids)` returns per-id features; `_contract(doc)` returns contract fields only.
- `worker._enqueue_new(tracks)` batch-checks `get_many_features` and `failed_ids`, then `put_track_meta` + `enqueue_embed` per new track.
- `app.recommend` ranks over the live matrix and walks the sorted order collecting `limit` results with `_tracks_cached`; `viz_map` does the same with a `skippable` widening and a snapshot filter. `_seed_cosine`/`_UNIT_CACHE` give unit vectors.
- Deezer titles: "(feat. X)", "(Remastered 2009)", "[Live]", "- Remastered", "- Live at …", "- Radio Edit", "- Single Version", "(Take 2)", "(Mono)", trailing "(1990 Remaster)".

### Task 1: Key, store fields, crawler guard, result collapsing

**Files:** create `src/music_recommendations/server/dedupe.py`, `tests/server/test_dedupe.py`; modify `store.py`, `worker.py`, `app.py`, `tests/server/test_store.py`, `tests/server/test_worker.py`, `tests/server/test_app.py`.

- [ ] `dedupe.py`: `normalize_title(t)`: lowercase; drop any `(…)`/`[…]` group that starts with feat/featuring/remaster/live/mono/stereo/take/version/edit/mix/demo/bonus/from/deluxe/anniversary or contains a 4-digit year; drop a trailing ` - …` segment matching the same word list; collapse non-alphanumerics to single spaces; strip. `normalize_artist(a)`: lowercase, drop anything after " feat"/" featuring"/" & "/", " (primary artist only), collapse non-alphanumerics. `dedupe_key(title, artist) = f"{normalize_artist(artist)}|{normalize_title(title)}"`. Tests: "So What (feat. John Coltrane…)" → "so what"; "Mood Indigo (1990 Remaster)" == "Mood Indigo"; "Take Five - Live at Carnegie Hall" == "Take Five"; "Miracle (with Ellie Goulding)" == "Miracle"; "Around the World (Radio Edit)" == "Around the World"; different artists with the same title produce different keys; "Blue in Green" vs "Blue In Green (Take 2)" equal; a cover by another artist is not equal.
- [ ] `store.py`: `_meta` adds `"dedupe_key": dedupe_key(title, artist)`; `ensure_indexes` adds an index on `dedupe_key`; new `existing_keys(keys: list[str]) -> set[str]` (one `$in` query over non-duplicate docs); `LIVE = {"analyzed_at": {"$exists": True}, "duplicate_of": {"$exists": False}}` used by `corpus_ids`, `base_matrix`, `tracks_since`; `mark_duplicate(track_id, primary_id)` sets `duplicate_of`; `get_features` unchanged (a retired track can still be seeded explicitly). Tests: key stored on put; `existing_keys`; a marked duplicate disappears from `corpus_ids`/`base_matrix`/`tracks_since`.
- [ ] `worker._enqueue_new`: compute keys for all candidates, call `existing_keys` once, skip candidates whose key exists or repeats an earlier candidate's key in the same batch; log `"… N queued, M duplicates skipped"`. Tests: a re-release of an existing track is not queued; two editions in one batch queue once.
- [ ] `app.py`: in `recommend` and `viz_map`'s result loops, skip a candidate when its key equals the seed's key or any earlier result's key, or when `unit[idx] @ unit[prev_idx] > 0.995` for any earlier result (use the cached unit matrix from `_similarity`'s `_UNIT_CACHE` for `embedding`; fall back to computing the two unit rows). Keep the loops O(limit²) at most. Tests: with three copies of the same recording in the corpus, `/recommend` returns each recording once; a genuine cover (different artist, cosine 0.9) is kept; the seed's own re-release never appears.
- [ ] Commit `feat(dedupe): dedupe keys, crawler guard, duplicate retirement, result collapsing`.

### Task 2: Backfill script and rollout

**Files:** create `scripts/dedupe_corpus.py`, `tests/server/test_dedupe_corpus.py`.

- [ ] Script: load all live analyzed docs (`_id, title, artist, analyzed_at, embedding, scale`); group by key; within each group keep the earliest `analyzed_at`, mark the rest `duplicate_of=primary`. Then an embedding pass within each artist: for tracks of the same normalized artist, mark as duplicate any pair with cosine > 0.995 that survived the key pass (keep the earlier). Print counts per pass and the top 10 groups; write only with `--apply`. Exit 0. Test on mongomock: dry run changes nothing and reports counts; `--apply` marks the expected docs and keeps the earliest.
- [ ] Rollout: push, PR, deploy the branch on the VM, run the script inside the api container in dry-run, then with `--apply`; restart the api container so its in-memory matrix reloads; verify `corpus_size` dropped by roughly the marked count, `/recommend` for a seed with known duplicates shows each recording once, worker log shows "duplicates skipped" on its next crawl.
