# Feel-Aware Ranking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make "More sounds like this" respect energy, mood and texture, not just style, with a live-tunable blend so the ranking can be tuned by ear.

**Architecture:** Eleven binary classifier heads trained on the Discogs-EffNet embedding (danceability, mood happy/sad/aggressive/relaxed/party/acoustic/electronic, timbre bright, tonal, instrumental) run on each track's stored 1280-d mean embedding — no re-analysis, 20k tracks in well under a second. The resulting `feel` vector (11 probabilities in [0,1]) is stored per track as a second feature key and loaded into a second in-process matrix through the existing multi-key `_corpus_matrix` machinery. The `sounds_like` score becomes `cos(embedding) − w · feel_dist`, where `feel_dist` is the mean absolute difference across the 11 dims and `w` comes from the `feel` query parameter (default 0.5). The web app exposes a slider and shows the per-dimension comparison in the math panel. A backfill script scores the existing corpus; the worker scores new tracks as it analyzes them.

**Tech Stack:** TensorFlow (heads via `tf.compat.v1` graphs, input `model/Placeholder:0` shape (None,1280), output `model/Softmax:0` shape (None,2)), numpy, pymongo, React.

## Facts (measured 2026-09-13)

- Heads (all under `https://essentia.upf.edu/models/classification-heads/<family>/<name>.pb` with a sibling `.json`; ~0.5 MB each): `danceability-discogs-effnet-1` classes `[danceable, not_danceable]`; `mood_happy` `[happy, non_happy]`; `mood_sad` `[non_sad, sad]`; `mood_aggressive` `[aggressive, not_aggressive]`; `mood_relaxed` `[non_relaxed, relaxed]`; `mood_party` `[non_party, party]`; `mood_acoustic` `[acoustic, non_acoustic]`; `mood_electronic` `[electronic, non_electronic]`; `timbre` `[bright, dark]`; `tonal_atonal` `[atonal, tonal]`; `voice_instrumental` `[instrumental, voice]`. The positive index is the class whose name does not start with `non_`/`not_`, except `timbre` (positive = `bright`), `tonal_atonal` (positive = `tonal`), `voice_instrumental` (positive = `instrumental`) — define explicitly per head rather than inferring.
- The 11 files are already downloaded on the Mac under `models/heads/` (gitignored). `scripts/fetch_models.py` must fetch them for the Docker image.
- `app.py` supports multiple feature keys: `_corpus_matrix(corpus, key, metric, want_correction)`, `_rows_for(ids, key)` via `store.get_many_features`, `_MATRIX_CACHE[key]`; `_cold_matrix` uses `base_matrix()` only for `"embedding"` and `_rows_for` for other keys. `AXIS_FEATURES["sounds_like"] = ("embedding", 1)`; `recommend` computes `similarity = _similarity(...)` then `rank_mod.rank(..., similarity=similarity)` then `_take` with `_Collapse`.
- `store.put_track(track, features)` stores `embedding` (int8) + `scale` + `features_version`; `get_features` returns `{"embedding": [...], "_features_version": n}`. `analysis.analyze_tracks(paths)` returns feature dicts with `embedding` (patch mean).
- `contract/features.py::FEATURE_KEYS = {"embedding": 1280}`; `tests/test_contract.py` asserts it.
